## Как устроено сейчас
- **Оболочка и экраны.** `index.html` содержит оболочку и 6 экранов-вкладок в `iframe` (`home, work, nutr, prog, prof, onb`), каждый грузится из строки FRAMES. «Библиотека» встроена в экран `work` (подвкладка 4, `lib` в FRAMES как отдельная копия). Размеры: onb 111 КБ, home 221, work 317, nutr 192, prog 176, prof 136, lib 101.
- **Данные.** Один модуль `FS` (хранилище в `localStorage`, префикс `forma.`) с проверкой типов. Ключи и значения по умолчанию: `profile{}`, `hist[]`, `wt[]`, `progs null`, `plan null`, `live null`, `set{wRem:true,notif:[]}`, `ob 0`, `sync{}`, `demo 0`, `pend[]`, `nutr null`. Дополнительно: `libq` (заявка на Библиотеку), `xarch` (архив). Копия `forma.*` пишется в IndexedDB `forma-mirror` каждые 30 с и при сворачивании; если систему очистила `localStorage`, данные и факт пройденного онбординга восстанавливаются. Выгрузка и загрузка: `FS.dump()` / `FS.load()`.
- **Форма данных (из кода).**
  - `progs.programs[]`: `{id,name,desc,workouts[{id,key,name,desc,done,tnote,ex[{u,id,mode,sets[{v,w,t,rest}],note,link}]}]}`.
  - `plan`: `{days[0–6],mins,time,prog,...}` (мутировать, не заменять; также `plan.items`, `plan.ex`, `plan.daysEnd`).
  - `hist[]`: `{d,k,wn,pn,t,sec,kcal,pct,vol,tn,ex[{id,n,mode,eff,my,pain,sets[{v,w,t,done}]}]}`.
  - `wt[]`: `{d:"YYYY-MM-DD",v:кг,demo?}`.
  - `profile`: `name,sex,birth,h,w,bf,goal,lvl,where,cau[],nut,coach{mode,code,name},preg,cx`.
- **Связь между экранами (`postMessage {f:"forma",t:…}`).** `hello`, `fs` (изменился ключ), `tab` (24 вызова), `swipe`, `open`/`sub` (открыть Тренировки в нужном месте), `find` (глубокая ссылка в Библиотеку: `q|eq|id`), `meal` (открыть «Добавить приём пищи»), `ob-done`, `redo` (повторить онбординг), `reload`, `show`, `libdock`, `coach-link/unlink/note/prog`. В React Native всё это превращается в навигацию с параметрами и подписки на хранилище.
- **Общие модули, дублируются в каждом экране.** `STORE, HIST, PULSE, COMMON (initSeg, swapPane, окна, нижнее меню), FZ (нечёткий поиск), RX (37 состояний + беременность), GEN (генератор), MIG (миграция id демо-каталога), SYNC`.
- **Платформенные вещи.** Safe-area (`--sai-*`), отключение задержки нажатия, поля не меньше 16px, `navigator.vibrate` (42 вызова, на iPhone не работает), WebAudio для сигналов таймера (2 места), камера в Питании (`allow=camera`): штрихкод ZXing и OCR этикеток Tesseract, 7 canvas, 92 SVG.
- **Данные.** Каталог `FCAT` 989 упражнений (`logic/fcat.json`), продукты: `data/base_products.json` (собственный справочник) и `data/ru_products.json` (Open Food Facts, ODbL, нужна атрибуция «Open Food Facts contributors»).

## Известные расхождения и риски в текущей PWA (найдены при подготовке)
1. **Шрифт Onest не подгружается.** `fonts/fonts.css` пустой с первого коммита, `@font-face` в проекте нет. На iPhone вместо Onest системный шрифт, а в ряде мест остаётся serif-стек (раздел «TYPE v3» в CSS и `--serif`). Решение о едином Onest от 6 октября в этой сборке не применено. Исправление: прописать два `@font-face` на файлы в `fonts/`. Не менял без твоего решения, потому что это изменит внешний вид.
2. **Связь тренер–клиент сейчас не работает вне артефакта.** `SYNC` использует `claude.use("db")` и `claude.use("user")`, доступные только внутри артефакта Claude. На GitHub Pages статус всегда `nolink`. В React Native нужен настоящий бэкенд.
3. **Автотесты лежат на Mac, не в репозитории:** `qa_full.py` (52 сценария), `audit_ds.py`, `e2e_wk_full` (35), `e2e_wk_rx` (50), `t_lib` (88), `t_prof`, `t_rx`, `e2e_sync`. Их надо принести в `legacy/tests/` как приёмочные сценарии. Mac в этой сессии не подключён.
4. Мастер-документ `app/SPEC.md` тоже на Mac, в репозитории его нет.
5. Известный остаток: чипы фильтров библиотеки 37px (невидимая зона нажатия 44), push-уведомлений нет, не проверено на реальном iPhone. У 19 строк каталога (id 942–953, 981–997) нет степени PAILs/RAILs, принято «с осторожностью».

## План переноса (порядок и способ)
**Принцип:** логику переносим как есть и проверяем эталоном, интерфейс переписываем заново, но по реестру, элемент в элемент.

| Шаг | Что | Как проверяем |
|---|---|---|
| 0 | Проект Expo (уже есть пилот `forma-rn`), токены, Onest (подключить по-настоящему), типы данных, хранилище с теми же ключами и проверкой типов, миграция MIG, экспорт/импорт `dump/load` | Схема данных совпадает с таблицей выше; загрузка `dump()` из PWA работает |
| 1 | Чистая логика: RX, GEN, FZ (поиск), даты, расчёт нагрузки, статистика программ, калькуляторы калорий и % жира (из `prof`/`nutr`) | Эталон `golden/starter.golden.json.gz` для GEN совпадает по 324 профилям; для калькуляторов эталон снять скриптом из PWA |
| 2 | Оболочка: нижнее меню «Капля», анимации иконок, «+» с двумя действиями, свайпы между вкладками, safe-area | Сверка со снимками `baseline/` |
| 3 | Онбординг | Все вопросы и порядок из памяти проекта, результат пишет `profile/plan/progs/ob` как сейчас |
| 4 | Главная | Реестр `home`; сценарии: календарь, перенос, повтор, ритм, вес линейкой, готовые программы |
| 5 | Тренировки: «Мои», «Готовые», «Клиенты», конструктор, живая тренировка, таймер, заметки, Библиотека | Самый большой блок. Реестр `work` + `lib`; сценарии e2e_wk_* |
| 6 | Питание: Дневник, Моя норма, прогноз веса, база продуктов, сканер штрихкода и OCR | Реестр `nutr`; нативная камера вместо ZXing/Tesseract |
| 7 | Прогресс | Реестр `prog`: «По неделям», упражнения, 1RM, медали, ритм |
| 8 | Профиль | Реестр `prof`: портрет, калькуляторы, данные, демо, напоминания |
| 9 | Нативное: haptics, локальные уведомления со звуками таймера, Live Activity и Dynamic Island (вариант 1) | Только на реальном iPhone |
| 10 | Бэкенд: аккаунт, синхронизация, связь тренер–клиент, продажа программ | Решение по Apple Developer и платёжной схеме |

**Что заменяется по природе платформы (это не потеря функций):** `iframe`+`postMessage` → единое приложение с навигацией и хранилищем; `navigator.vibrate` → настоящие haptics; WebAudio → локальные уведомления и звук; `localStorage`+IndexedDB-зеркало → хранилище на устройстве; ZXing/Tesseract → нативная камера и распознавание.

## Правило паритета
Функция считается перенесённой, когда: (1) для каждого пункта реестра экрана есть работающий аналог (отмечаем в чек-листе экрана), (2) логика проходит эталоны, (3) снимок экрана сопоставлен с `baseline/`, (4) пройден сценарий пользователя на реальном устройстве. Удалять или менять поведение разрешено только по твоему слову.
